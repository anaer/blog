# ADR-0001：生成管线正确性——内容收录与构建状态

**状态：** 提议中
**创建时间：** 2026-09-30

> **当前状态 / 核心结论：** 4 类正确性缺口已定实施口径——全量重建索引、明确收录过滤、摘要失败可重试（上限 10 条/构建）、置顶按最新事件判定（已线上实证）；下一步进入 SPARC 流程实施（批次 A）。

---

## 背景

博客以 Issues 为唯一内容源，构建状态持久化在 `blogBase.json`（文章索引 + 摘要/构建缓存）。本轮分析确认：全量构建从不清空索引，已删除文章与改判条目永久残留（`Gmeek.py#GMEEK.runAll` 的实际行为与代码注释声称的「每次执行会先清空」不符）；拉取 issue 的接口同时返回 PR，现有过滤只判作者；AI 摘要为空时仍写入构建缓存，失败后永不重试（线上 `blogBase.json` 已存在空摘要条目）；置顶检测正向迭代事件、遇到旧 `pinned` 即中断，取消置顶很可能不生效。

## 决策

1. **全量构建重建索引**：全量构建显式重建 `postListJson`/`singeListJson`，不再继承上次落盘内容；对「更新时间未变」的旧条目携带 `description`/`buildedAt`/`renderVersion` 缓存，避免重复 AI 调用与 HTML 重转（`renderVersion` 供渲染器变更时全站失效，见 ADR-0005）。
2. **收录过滤明确化**：仅收录仓库主创建、且非 PR（`pull_request` 为空）的 issue。
3. **摘要失败不固化**：仅在成功取得非空摘要时写缓存；请求失败/空结果留空待下次构建重试，重试上限 10 条/构建（防 API 故障时超时叠加拖死构建）；API 未配置时跳过不重试。摘要函数需区分「未配置」与「失败」两种返回语义。
4. **置顶按最新事件判定（REST 事件接口）**：取 pin/unpin 事件中创建时间最大的一条（与接口返回顺序无关）——pinned 判置顶、unpinned 判非置顶；已实测事件按升序返回且 unpinned 事件存在。
5. **状态文件瘦身**：`blogBase.json` 只持久化内容索引与缓存字段，不再落 `prevUrl`/`nextUrl`/`labelColorDict` 等展示态。
   - 不做什么：不改「已关闭 issue 保留且列表排最后」的既有语义；不在本批优化逐 issue 拉取事件与评论数的 API 成本。

## 后果

- **收益：** 删除/改判的文章不再残留；PR 不会被误收录；摘要失败可在后续构建自愈；状态文件职责清晰。
- **代价 / 权衡：** 每次全量构建重建索引，缓存携带规则需写清并有测试兜底。
- **未解决风险：** pin/unpin 事件在时间线中的行为（顺序、是否保留历史事件）需实施时实测。
